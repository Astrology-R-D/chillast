# AI 诊断与工具路由

设置中的“诊断日志”提供“打开日志目录”和“导出诊断日志”。日志位于 Electron 的 `userData/logs/`，Windows 默认是 `%APPDATA%/chillast/logs/`。无需开启开发者工具；主进程启动后自动记录。

日志是带 UTC 时间的 JSON Lines，单文件约 2 MiB，最多 5 个轮换文件。导出的 ZIP 包含这些日志及软件/运行时版本、聊天模型标识、工具启用和就绪状态；不包含会话数据库、知识正文、工具参数/结果或出生档案。API Key、认证头和 URL 凭据/查询参数会被过滤。没有写入权限时日志失败不会阻止软件运行，设置中会显示写入错误。

诊断事件包含：启动、渲染器加载/崩溃、IPC 失败、AI 连接测试的服务商/模型/接口及耗时、超时或 HTTP 错误、对话路由与工具名称、工具执行状态与耗时、报告修复、网页读取/搜索失败、主进程异常。错误保留经过过滤的堆栈；控制台警告/错误只记录首个消息或 Error 摘要，不复制任意 SDK 请求对象。

连接测试使用独立的小输出预算，最长等待 60 秒，不再在 15 秒固定中止。测试不启动嵌入模型。超时、401/403、404、429、服务端失败和网络错误各有对应提示；测试不会替换已保存配置。`Query aborted` 也可能来自其他取消行为，只有本次超时信号触发或提供商报告超时时才标为超时，实际用户原因应结合日志判断。

AI 工具不依赖生成星盘。命理/占星分析继续经过分析报告、引用校验和回答两阶段；没有盘面且未命中分析关键词的实质请求交给通用工具 Agent，可直接读取用户提供的网址、联网、查档案或使用已启用的 MCP 工具。纯寒暄/确认仍使用轻量回答。所有路线遵守工具的启用/就绪状态；工具被关闭时不会偷偷启用。通用工具对话保留完整工具结果与来源快照，不产生虚构判据报告。

排查反馈时让用户先复现，再在设置导出 ZIP。先查看 `ai-connection-test-failed` 的 `timedOut`、`status`、`code` 和 `durationMs`，再检查 `ai-turn-start` 的 `route`/`tools` 与网页错误。日志不包含完整问题；用户对问题的描述仍然必要。

报告引用失败时，`ai-analysis-repair` 记录事实/来源数量，以及 `validation` 中的判断 ID、具体字段路径和无效引用的哈希指纹；不记录原始报告、引用文本或用户原话。修复后仍有问题的判断记录为 `ai-analysis-claims-rejected`。JSON 格式错误使用固定诊断文本，避免解析器把报告片段写进异常日志。旧版日志只有统一报错时，不能据此确定具体哪个引用编号有误。

首次报告和补充探索后的每轮报告共用校验入口，各有一次格式/引用修复机会，完整性探索最多重试两轮。修复保留原问题与工具原文作为依据；仍不合法时隔离整条判断，不会只删除引用、保留结论。其他合法判断仍需通过对象、时间和适用条件检查。修复结果格式损坏时尝试保留原报告中合法的判断；全部判断仍无法通过校验时，以说明资料已保留的提示正常结束，不输出这些判断，也不把内容校验问题显示为请求失败。判据目录直接合并 Agent 状态中的工具结果，不依赖界面消费更新事件的速度。

一般分析错误通过 `ai:error` 结束生成；只有正在压缩时的失败才发送压缩错误。开始新回复时清理上一轮上下文提示，避免旧错误与新的工作状态同时显示。

工具调用额度按工具独立计算，可在设置的“工具与 MCP”中修改，默认每个工具每轮 32 次，0 为无限制。设置按工具调用名称长期保存到 toolCallLimits；新工具自动枚举，暂时离线的工具配置仍保留。会话检索工具同样可配置。分析与补充查证共享当前用户消息的计数，失败的执行也计数；配置修改下一轮生效。旧的全局 32 次和重复查询两次限制已移除。工具耗尽后从下一批模型请求的可用工具列表移除，不影响其他工具；全部耗尽时通过不绑定工具的请求整理结果。同批并发超额调用不执行并记录 kind: budget。无限制可能持续探索，用户仍可停止。引用校验保持不变。

回答正文的专业术语检查属于表达质量检查：先要求模型改写；改写后仍残留术语时记录 `ai-answer-style-fallback` 并保留回答，不再因此中断整轮。引用存在性、假设的不确定性标记、段落格式和主要判断覆盖仍须通过检查。普通措辞如“符合相关要求”不会再被其中的“合相”字样误判为相位。此降级可能保留少量术语，不会自动删词或改写数值造成语义变化。

回答段落的格式、引用、假设限定及覆盖问题先进入暂存区，最多调用两轮不带工具的 AI 自动修正。每轮提供校验反馈、尚未覆盖的判据和已发布内容，避免重复；修复段落逐条验证，合格段落继续输出。修复仍不成功时仅省略问题段落并显示部分回答提示；没有合格正文时显示未形成可核对结论的说明。`ai-answer-repair` 和 `ai-answer-partial` 记录修复次数和缺口，不包含正文。停止操作会取消修复，网络或认证等真实请求失败仍按请求错误处理。
