# AI 任务与资料完整性

本次改造把“能调工具”和“可以发表分析判断”分开。普通请求可以查网页、档案；工具返回星盘、八字或知识内容后，在整批工具结束的图执行边界升级到分析阶段，携带原始工具消息，不让旧图继续执行或直接输出技术解读。

## 时间与对象

每轮任务记录实际时刻、IANA 时区、解析后的目标日期、对象 ID 与出生输入指纹、计算设置和知识库指纹。相对日期以本轮本地日期重算；固定历史日期不随系统日期变化。自然追问继承原问题的时间类型，相对日期重新锚定。周、月、年与数字天数范围保留边界；日级问题至少需要对应日期的动态计算，范围问题至少核对两端（年运可以使用对应年度的太阳返照）。这只是范围覆盖的最低条件，不能据此声称确定期间的精确事件。

“此刻/实时”需要与本轮时刻相差不超过一分钟的计算。计算工具新增带时区的 `targetDate`；旧年月日输入继续使用 12:00 UTC 的日级快照。次限的推运天文时刻与用户查询目标日期分开保存。未知来源的旧计算必须重新取得出生输入和目标日期，不能只因图表存在就信任。

档案修改后，下一轮按当前资料重算出生指纹。计算设置取已成功应用的设置，不把尚未计算的界面草稿当作结果。一次请求中的界面上下文与时钟固定，用户切页不改变正在进行的工具读取。

## 逐条检查与补查

专业解释类判断需有具体判断、可公开的简短依据说明、计算/来源引用、适用条件与相反依据检查。程序独立验证：

- 引用实际存在；个人解释同时有计算事实和解释来源，档案摘要不能冒充星盘。
- 计算出生指纹、宫位制、黄道及相位设置匹配任务。
- 时间目标覆盖本轮问题，旧行运不能充当今天的数据。
- 适用条件有明确描述、验证状态及事实和来源关联。
- 不能仅引用目录、摘要或概述；历史引用要在当前启用资料中重新查阅。
- 标注待核对的 OCR 数字不能直接支撑确定的数值结论。

失败项以结构化反馈交还分析 Agent，允许额外两轮工具补查。每轮任务最多 32 次工具调用，同一名称和参数最多两次；探索阶段最多 12 轮，分析图每次最多 25 步。预算耗尽后仅保留通过检查的判断，公开具体缺口，不把局部失败包装为全部资料齐全。档案查询和纯计算不强制附加解释书籍。

时间、引用和参数匹配是程序检查。来源是否真正支持结论、所有语义条件是否穷尽，仍依赖模型审阅，并非数学证明；应通过真实模型样本持续评估。`ready` 表示已通过当前规则，不代表占星解释已成为客观事实。

## 对话内容协议

报告保留 `version: 1` 兼容已有会话，以 `dialogueVersion: 2` 标记新增字段。旧报告默认视为专业解释。新内容分为：

| kind | 含义 | 校验重点 |
| --- | --- | --- |
| fact | 工具取得的事实，或注明是用户报告的情况 | 真实工具引用或逐字用户引用，不能用标签把心理推测变为事实 |
| interpretation | 专业框架解读 | 计算、来源正文、适用条件及时间匹配 |
| hypothesis | 尚待检验的解释假设 | 依据、对问题的含义、什么会改变判断；专业依据仍严格核对 |
| reflection | 回应用户表达的感受与需要 | 引用真实用户表达，不强行要求星盘或书籍 |
| suggestion | 围绕目标的可选行动 | 用户原话、适用情境、行动与取舍 |

`basis` 区分 `tool`、`symbolic`、`conversation`、`mixed`。会话内容用 `userRefs` 引用最近八条原始用户消息，服务端逐字核对；AI 回复、压缩摘要不能冒充用户确认。用户陈述本身不等于外部查证事实，疑问也不等于已经发生的事件，仍须模型在语义层区分。

核对项区分 `data`、`applicability` 与 `reality`。未取得出生输入、时效计算或来源适用条件仍阻止相关专业判断；尚未得到当事人直接确认的动机可保留为 hypothesis，其 reality 状态保持 unresolved。反向线索、竞争解释及 `whatWouldChange` 帮助避免无法证伪的两头堵套话。仅凭占星象征不能宣称知道对方实际想法，也不生成虚假的概率。

局部资料缺口仅剔除依赖它的条目，其余情绪回应和选择仍进入写作阶段；移除统一的“部分依据未完成”正文前缀，改为交给写作阶段按实际影响局部说明。没有出生精度标记表示 unspecified，不能把 12:00 自动当作未知时间；当前没有实现出生不确定区间的计算引擎，模型无法核实稳定性时须保留相关判断。

## 正文与判据

写作 Agent 接收已通过的判断，以及公开依据说明、对处境的含义、竞争解释、修正线索、行动选项和沟通示例，不接收整段专业原文及计算清单。共同的 `DialoguePolicy.js` 规定：先回应问题，结合具体描述展开含义与选择；温暖回应不等于巴纳姆，反巴纳姆针对无依据的人格归因和个性化预测。不得保证复合、诊断人格或承诺疗效；不把边界说明变成回答主体。

回答输出逐行 JSON 段落，程序校验判据 ID 后生成 Markdown 链接。事实、专业解释和假设的主要内容须覆盖；情绪回应与建议可自然融合，不为覆盖 ID 机械补一段摘要。假设首次出现必须有可见的不确定性措辞，后续展开无需重复免责。此为基础词面检查，不是对断言力度的完整语义验证。空回答会进入修复，仍为空则报错，避免无声结束。

错误段落不先显示，最多进行一次剩余段落修复。默认正文拦截度数、宫位和常见相位明细；用户明确索要技术解释时允许。假设显示为“解释假设”卡片，展开可见用户描述、解释依据、替代解释、何时调整判断和原始来源。历史判据保持兼容。压缩记忆同时保留 kind、basis 和修正线索，避免把上轮假设当作本轮既定事实。

日志新增 `ai-route-promoted`、`ai-readiness-retry`、`ai-readiness-checked`，只记录流程、状态和失败代码，不记录问题正文、出生输入或引用原文。

## 验证

`AnalysisReadiness.test.js` 覆盖跨时区换日、历史日期、区间、当前时刻、出生信息修改、设置变化、引用质量与逐段呈现。`AiTaskFlow.test.js` 使用真实 LangGraph 和本地模拟模型接口，验证口语问题在未打开星盘时自动升级，错误日期触发额外计算，次日追问刷新目标日期且复用本轮工具结果。模拟测试验证程序约束，不替代真实模型对语言自然程度、反巴纳姆和条件充分性的评估。

`AiDialogue.test.js` 覆盖无星盘的会话假设、真实用户引文、缺失依据、首次假设限定、非重复表达和空回答修复。`AiDialogueFlow.test.js` 用本地模拟接口验证：一条专业结论未通过检查，不会清空其他已通过的会话假设和支持。React 测试验证“解释假设”卡片及未确认状态。

可选真实模型评估：`npx electron tools/evaluate-ai-dialogue.cjs --saved-config`，只向当前保存的模型配置发送五个虚构场景，不读取真实档案或历史对话；可以用 `--case=relationship` 单独运行。输出到 `release/dialogue-eval.json`，不会记录密钥。场景覆盖关系动机、自我怀疑、职业选择、用户纠正与缺少出生信息。人工重点检查是否直接回答、是否解释到位、是否有具体选择、是否反复免责，以及是否将假设说成事实；篇幅不能替代质量评分。保存配置无法读取时脚本会退出，不改写配置。
