# 按书籍与章节组织的知识库

预准备器新输出：一本来源文档对应一个 `.kbunit`，正文按清洗后的阅读顺序保存。
不再按相位、宫位等领域重排正文。多个单元仍可组成一个 `.kbpack`。

## 结构与兼容

v1 容器增加可选 `structure` 元数据，由共享的 `KnowledgeStructure.cjs` 确定性生成：

- 章节 ID、父章节、标题路径、正文偏移和行号。
- 段块 ID、所属章节、前后块关联。块不跨 Markdown 章节边界，最多 1000 UTF-16 字符。
- 正文、概述、目录、序言、出版信息、案例等类型。
- 非互斥主题标签。目前基于中英文术语规则推断，不代表人工审核的分类。

类型和标签是检索提示，不修改正文。表格及长段落仍可能跨块，需要相邻读取。
代码块中的 Markdown 标题不会创建章节。引用行号是整理文本行号，不冒充原书页码。
结构校验重新计算正文对应关系，拒绝伪造或过期的范围、章节及类型信息。

旧 v1 `.kbunit` / `.kbpack` 继续读取，未携带结构的包在建索引时派生结构。
旧领域文件仍是独立文档，不猜测恢复其原书次序。要获得完整的跨章节阅读关系，
需要从 `whole-book.md`、清洗整书副本或原始书籍重新准备。直接换后缀无法恢复丢失顺序。
旧内建向量索引保持原样；在内存中推断局部标题信息，原有引用文本不改写。
包索引缓存版本已更新，首次加载需要重新建立索引；归档中的来源快照保持不变。

## 查询和续读

`search_knowledge` 使用关键词与向量候选做排名融合，默认返回最多 6 段。
每个索引取最多 24 个向量候选，关键词取最多 48 个候选；去除完全重复的文本。
普通查询降低概述、目录及序言权重；明确查询概述或目录时不降权。
这不是学习型重排序模型，也不是解释真实性校验器。

`read_knowledge(blockId, radius)` 读取命中段和前后各 0–2 段，默认 1。
块 ID 只在本轮启用的资料快照内解析，不能访问任意文件或未启用的包。
续读结果与检索结果使用同一来源快照和引用机制；来源卡片显示章节路径及类型。
知识包版本切换不会改变正在生成的回答所用资料。

分析 Agent 应检查解释的适用条件与例外，按需续读、补充计算或再次查询；
已有直接依据且重要相反依据已核对时结束，不无限重复探索。

## 已知限制

主题标签和内容类型依赖标题及术语，OCR 丢失标题时识别会受影响。
向量候选的跨语言效果仍取决于嵌入模型。
本次未对历史书籍执行收费清洗，也未自动替换用户安装的知识包。
生产端的字符保留率检查仍不能证明语义完整性，需要抽样核对关键条件、表格和数值。
